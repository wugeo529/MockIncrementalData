# PostgreSQL 消费端兼容性记录 · 2026-11-04

本次更新只补充消费端兼容性边界，没有新增模拟器代码，也没有重新打包 0.1.0。

## 模拟器已有能力

模拟器向自己配置的 `signal_sim_*` 数据库提交 GPS、IP 会话、target 三表的普通 INSERT / UPDATE / DELETE 事务。MySQL Binlog 与 PostgreSQL WAL 由数据库产生，采集、RAW、画布、LAKE 和 Mapping 属于独立消费平台。本仓库不包含 WAL 读取器，也不会创建复制槽、发布或平台任务。

2026-11-04 比对了当前平台本地汇总和本地验收工作树的 `scripts/data-access/multitable-signal-source/signal_source.py` 与本仓库 `engine/signal_source.py`：忽略换行差异后内容一致，没有待迁入的更新生成逻辑。独立桌面连接管理和安全修复继续保留，不用平台脚本覆盖。

## 外部平台本地验证

维护者提供并复核的 2026-11-04 本地验收报告记录：PostgreSQL 14.22 的三张独立合成测试表，经 WAL → RAW → 布尔筛选画布 → 同一 LIVE revision → 公开 Mapping，实现新增、修改、删除、筛选撤回及未映射字段修改的 Success 观察；Mapping 暂停/恢复及应用重启后继续消费通过。

该验证使用平台专用 `pg1_signal` 测试表和独立 DML fixture，**没有通过本模拟器桌面界面生成这些测试数据**，也不是本模拟器 GPS/IP/target 三表到 Mapping 的联合验收。它提供 PG14 消费链路的外部证据，不扩大本模拟器原有源端验收结论。

外部报告：`PG到Mapping闭环验收-20261104.md`，作者/责任人 wugeo529；本地平台工作树基线 `5116e5ab8`，报告包含未提交实现，不能把基线提交描述为该能力的发布版本。报告 SHA256：`0449cc4d14938eaf59b00e6f86471571348cb87280d0b46185f66197c81a1505`。原始证据名称为 `native-all-changes.json`、`recovery.json`、`browser-flow.json`；这些属于平台本地验收资料，没有复制进本公开仓库。此记录不提供尚不存在的公开平台发布链接。

## 使用与限制

使用者仍须独立配置消费平台、数据库 WAL/复制权限、采集表和下游处理；模拟器连接账号与平台采集账号分别管理。数据库须使用模拟器支持的专用结构，不能把本报告的外部 fixture 当作本模拟器可直接初始化的库。

Linux 新主机安装、其他 PG 大版本、生产容量/HA/72 小时长稳、PG 原生冷备份均未由该外部报告取得资格。Windows 0.1.0 原有下载和校验值保持有效；本次没有改变安装包或用户保存的连接设置。
