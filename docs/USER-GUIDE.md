# 从零使用

## 准备数据库

本程序连接你已有的数据库服务器。若不知道连接账号，请向该数据库的管理员获取；安装包没有通用数据库密码。

在本机 MySQL 已启动的前提下，点“数据库连接”，使用你自己的主机、端口和账号。首次建议数据库名 `signal_sim_demo`。测试连接只认证、查看数据库与三表结构，不会写入数据。

“保存连接”将本次会话切换到该源；自动模拟运行时请先停止，避免途中更换目标。密码留空只会沿用**同一主机、端口、数据库和用户名**的已有密码；更改目标后需重新填写。

首次没有数据库或表时，保存后点“初始化模拟表”，确认后创建三表并写入6组数据。没有建库权限时，请管理员先创建专用空库，再授予三表建表/读写权限。已有完整结构只校验；不兼容或部分结构不自动改造。

## 每个按钮做什么

|按钮|效果|在哪里核对|
|---|---|---|
|测试连接|认证并检查目标库/表是否存在；不建库、不写业务数据|连接窗口状态文字|
|保存连接|切换当前数据源；可选择本机加密保存密码|主界面的主机/端口/数据库文字|
|初始化模拟表|显式创建专用库、三表与6组数据；已有结构保留|GPS/IP/target各6条初始数据|
|新增一批|GPS和IP新增一条，target按终端身份新增或更新|计数、最新表、提交日志|
|修改最近记录|最新GPS的速度/方向、IP报文长度及对应档案等级更新|同一记录ID的字段变化|
|删除最近一批|确认后删除最近GPS/IP及对应目标档案|计数减少、记录消失|
|开始自动模拟|按设置间隔、批数执行混合增删改|运行状态、本轮进度、提交日志|
|停止自动模拟|请求结束当前批次，不撤销已提交事务|状态变为已停止|
|刷新数据|重新读源库计数和每表最新10条|读取时间|
|GPS/IP会话/目标档案|切换正在观察的源表|表格列名和内容|

GPS/IP一般逐批增长；target轮流维护6个终端，所以三表行数不一定相等。删除最新行后再新增可能复用最新可用ID；不以ID连续性充当提交位点。

## 接到自己的消费系统

本程序只负责源端数据。MySQL需要开启适合消费端的Binlog配置，并由消费端选择三表、配置采集账号和稳定主键。消费端首次读取基线后，再消费新增/修改/删除。发送间隔在模拟器设置；采集方式与消费端Pipeline设置在消费系统中设置。

MySQL演示版给IP的id建主键，target增加_sim_id技术主键，GPS浮点字段改为DECIMAL(20,8)。PostgreSQL原结构保留相应浮点字段及原来未显示主键的表，不伪造“已可WAL消费”。

迁移主机：复制对应系统安装包 → 准备目标数据库 → 重新填写连接 → 初始化或核验三表 → 配置消费端。若迁移已有源数据，另做数据库备份恢复；安装程序本身不携带你的数据或消费位点。

不要把Windows安装包用于Linux/macOS。其他系统从项目构建任务取得对应产物，并在目标系统验收。
